# 当前玩法现状与游戏化重构讨论输入 v34

**状态**：当前实现审计；用于玩法重构讨论，不是未来方案

**审计日期**：2026-07-29

**目标读者**：外部游戏设计 AI、系统设计师、经济模拟设计者、后续开发者

**审计基线**：`refactor/cpp-m11-v34`

> 本文描述 Macro Command 当前“玩家实际上能够经历什么”，并区分已接通的功能、
> 仅存在于界面或协议中的功能，以及设计文档中提出但尚未形成完整运行链路的功能。
> 讨论未来玩法时可以推翻现有前端结构，但应尊重已经建成的经济模拟能力和前后端边界。

---

## 0. 一句话结论

Macro Command 当前是一套功能丰富的**多经济体模拟沙盒与宏观数据终端**：
玩家可以创建世界、配置国家、推进自然时间、观察宏观和微观主体，并在设计上通过政策
工作台干预经济。

它目前还不是一个完成的经济经营游戏，原因不是缺少更多指标或页面，而是缺少一个围绕
玩家决策建立的完整闭环：

```text
目标或使命
  → 识别问题
  → 作出有代价的选择
  → 等待并承受结果
  → 理解因果
  → 获得阶段评价
  → 胜利、失败或进入下一阶段
```

当前主要循环更接近：

```text
配置世界
  → 推进时间
  → 阅读大量数据
  → 尝试调整政策
  → 继续推进并观察
```

同时，当前桌面运行链路还残留“自由政策沙盒”和“Controller / 席位治理”两套互相冲突
的控制语义，导致正常从开始菜单进入后，政策操作未必能够形成合法提交。这属于必须先
解决的产品断链，而不是玩法平衡问题。

## 1. 当前产品身份

### 1.1 玩家扮演什么

界面把玩家放在“宏观指挥室”中，实际可接触的主要权力是国家政策：

- 财政与公共支出；
- 货币与中央银行；
- 金融监管；
- 外交、贸易与跨境制度；
- 能源政策；
- 劳工与社会保障。

玩家不能直接操纵单个家庭、个人、企业或证券交易。家庭、企业、股市和世界视图目前
主要承担观察与解释功能。

因此，当前隐含角色接近“拥有跨部门政策权力的国家宏观管理者”，但游戏没有正式定义
玩家的宪政身份、任期、政治授权、选民基础、国家使命或责任边界。

### 1.2 当前更接近什么类型

按照实际功能，它最接近以下三者的组合：

1. 多经济体 Agent-based 经济模拟器；
2. 可自由调参的政策实验室；
3. 金融财经风格的数据可视化终端。

它还不具备典型经营或策略游戏中稳定存在的目标、资源约束、对手、阶段推进、反馈奖励
和结算。

### 1.3 当前模拟底座

- 后端正在迁移为原生 C++ 经济引擎；
- 时间单位为自然日，`1 tick = 1 日`；
- 世界可以包含多个经济体；
- 经济体内部存在个人、家庭、企业、银行和政府等主体；
- 世界可以启用贸易、资本流动和人口迁移；
- 政策、外生冲击、指标发布和桌面协议已经模块化；
- 长期目标规模是数百万级 Agent，而不是早期千人级展示模型；
- 前后端分离，Godot 客户端原则上只是一个可替换的交互与可视化层。

## 2. 当前完整玩家旅程

### 2.1 首页

玩家进入开始菜单后，主要动作是：

- 新建模拟；
- 打开设置；
- 进入当前或已有模拟的入口；
- 退出。

游戏内顶栏有返回主菜单按钮。不过当前“返回主菜单—继续模拟”的运行语义尚未闭合，
详见第 8 节。

### 2.2 新建模拟

当前新建模拟是五步流程。

#### 第一步：选择场景

当前提供：

- 自由沙盒；
- 石油禁运；
- 全球金融危机；
- 大流行；
- 自然灾害。

场景不是纯文案。后端会生成真实的 ShockTape，并在设定日期对目标经济体施加生产率、
需求、劳动、信贷、贸易或资本等约化冲击。

玩家在开局前已经知道所选危机的类型，因此这些场景更像“已知压力测试”，不是未知的
游戏事件。

#### 第二步：配置世界

玩家可以设置：

- 国家数量，当前 UI 范围为 1–8；
- 随机种子；
- Gregorian 开始日期；
- 运行时长，可按年月日、天数或无限配置；
- 是否启用国际贸易；
- 是否启用跨境资本；
- 是否启用人口迁移；
- 汇率、资本流动、迁移等高级世界参数。

界面以自然日期为主要时间表达，tick 只作为顶部参考数字保留。

#### 第三步：配置国家

玩家逐国设置国家身份和经济结构。

可选 Profile 包括：

- 对称基线；
- 发达；
- 发展中；
- 转口港；
- 资源国；
- 自定义。

可覆盖的结构配置包括：

- 初始人口；
- 消费品、资本品、能源和建造企业数量；
- 银行数量；
- 基础生产率和资本份额；
- 银行、债券、资本市场、住房、人口、能源等机制开关；
- 其他创世和结构参数。

人口由玩家直接设置，家庭账户由创世阶段的人口、婚姻、亲属和家庭匹配算法生成。

界面支持两类比例映射：

- 基线配置变化后，其他 Profile 按比例更新；
- 人口变化后，企业数量按比例更新。

当前玩家国家实际固定为国家列表中的第一个。旧的“政府与席位”步骤曾允许选择玩家国，
但该步骤已经从现行五步流程移除。

#### 第四步：配置初始政策

初始政策页面读取引擎 Policy Registry，而不是维护独立的前端参数表。

当前约有：

- 102 个政策杠杆；
- 6 个政策部门；
- 12 个左右的主题分组；
- 每个国家各自独立的初始政策。

玩家可以搜索、筛选和覆盖政策值。初始政策作为 t=0 已生效状态进入模拟。

#### 第五步：检查并启动

确认页汇总：

- 世界和时间范围；
- 国家与 Profile；
- 结构能力；
- 初始政策；
- 场景；
- 随机种子和复现信息。

启动时，Godot 发送版本化 `NewGameSpec`，原生后端校验成功后创建世界，再进入宏观
指挥室。

### 2.3 进入宏观指挥室

主界面由三列构成：

- 左侧：政策工作台；
- 中间：宏观、主体、市场和世界可视化；
- 右侧：事件时间线与重要事件；
- 顶部：日期、tick 参考、关键指标和时间控制。

### 2.4 推进模拟

玩家可以：

- 单步推进 1 日；
- 播放或暂停；
- 使用 1×、5×、15×、60×速度。

当前速度按钮本质上控制每次客户端推进请求包含多少个模拟日。经济引擎仍按日执行经济
动力学。

### 2.5 阅读公报和指标

指标不是全部即时发布。系统区分：

- 指标对应的经济参考期；
- 实际发布时间；
- 当前日期是否已经可以获知；
- 尚未发布或缺失的数据。

因此玩家原则上不能用未来数据决策，开局时也会出现一段“尚未发布”的数据空窗。

### 2.6 调整政策

产品设计目标是自由政策模式：

- 所有已注册且适用于当前经济体的政策都可见；
- 玩家可以在任意干净的日边界编辑；
- 同一批修改在下一模拟日开始前统一校验；
- 校验成功后原子生效；
- 不使用席位权限、会议、投票、行政成本、冷却、最小维持期或最大调整步长；
- 仍然保留类型、范围、能力依赖和联动政策等经济状态约束。

但是当前原生桌面适配器仍按 `controller` 模式声明控制语义，而开始菜单又把各政策席位
输出为 `null`。所以“自由编辑—下一日生效”的完整路径目前没有在真实桌面开局流程中
稳定成立。

### 2.7 接收事件和继续观察

时间线可以显示：

- 外生冲击公告、开始和结束；
- 政策相关事件；
- 风险警报；
- 系统和模拟生命周期事件。

玩家继续推进，查看指标、家庭、企业、市场和国家关系的变化。目前没有强制的阶段结算
或最终结算。

## 3. 当前已经具备的观察系统

### 3.1 顶部八项指标

顶部固定展示八个跨维度核心指标：

- 实际产出；
- 失业率；
- 通胀；
- 物价指数；
- 政策利率；
- 赤字 / GDP；
- 银行准备金；
- 贫困率。

每张卡显示最新已发布值、变化和短期趋势。

### 3.2 宏观焦点

宏观焦点当前承担“决策简报”功能，包括：

- 公报覆盖程度；
- 经济增长动能与价格压力构成的经济相位；
- 当前主要风险；
- 政策传导状态；
- 数据可信度；
- 八个核心维度的摘要。

它更像自动生成的宏观摘要，还不是会提出方案、解释原因或对玩家决策负责的顾问系统。

### 3.3 指标全景

指标全景已经按主题拆分成信息密集的子页面：

1. 实体经济；
2. 国民账户；
3. 劳动力；
4. 价格与货币；
5. 财政；
6. 银行与信贷；
7. 债务与风险；
8. 资本市场；
9. 住房市场；
10. 能源；
11. 外部部门；
12. 分配与福利；
13. 人口社会；
14. 企业生态。

页面中包含数值卡、折线图、柱状图、结构图、人口金字塔、劳动状态流转、年龄组劳动
参与率、债务结构、账户构成等多种可视化。

### 3.4 家庭

家庭页面可以查看：

- 家庭列表和家庭详情；
- 每个家庭的成员；
- 每个成员的人口学信息；
- 家庭和成员资产；
- 债务；
- 消费；
- 就业状态；
- 当前雇主。

已就业成员可以跳转到对应企业。

### 3.5 企业

企业页面可以查看：

- 企业列表和单个企业详情；
- 所属行业；
- 生产、收入、利润和成本；
- 资产、现金和负债；
- 就业与工资；
- 股权和市场相关信息；
- 员工列表。

员工可以跳转回对应个人或家庭详情，形成个人—企业双向连接。

### 3.6 股市

股市页面使用引擎已有指标构建现代市场看板，展示：

- 市场和证券概览；
- 价格和市值相关数据；
- 企业权益和市场表现；
- 证券列表与企业详情跳转。

系统不伪造后端没有提供的 OHLC 或盘口数据。

### 3.7 世界视图

世界视图可以查看：

- 各国宏观卡片；
- GDP、失业、通胀、汇率等比较；
- 贸易、资本与迁移关系；
- 多国排名；
- 国家综合表现雷达图。

当前雷达图由前端计算，包含七个维度：

- 繁荣增长；
- 充分就业；
- 价格稳定；
- 财政韧性；
- 金融稳定；
- 民生分配；
- 外部与能源韧性。

其权重和目标区间目前是前端固定规则，只用于展示，不是引擎任务、正式得分或胜负条件。

## 4. 当前玩家能够做什么

| 行为 | 当前状态 | 说明 |
|---|---|---|
| 创建多国世界 | 已接通 | 可配置国家、日期、期限、跨境机制和种子 |
| 配置国家结构 | 已接通 | 人口、企业、银行、能力和生产结构 |
| 配置初始政策 | 已接通 | 通过 Registry 生成表单并进入 t=0 |
| 推进与暂停时间 | 已接通 | 按自然日推进 |
| 查看延迟发布的数据 | 已接通 | 保留信息滞后和缺失 |
| 查看家庭与个人 | 已接通 | 主要为只读观察 |
| 查看企业与员工 | 已接通 | 主要为只读观察 |
| 查看股市与世界关系 | 已接通 | 主要为只读观察 |
| 经历外生冲击 | 已接通 | 开局场景可生成真实 ShockTape |
| 运行中自由修改政策 | 设计明确，桌面链路未完整接通 | 自由政策协议和原生适配仍不一致 |
| 直接控制家庭、企业或交易 | 未实现，也不是当前产品方向 | 微观主体由引擎行为规则驱动 |
| 与外国政府谈判 | 未形成玩法 | 世界有经济关系，但没有外交决策循环 |
| 面对主动的外国政策 AI | 尚未形成稳定产品行为 | 其他国家不构成清晰的策略对手 |
| 保存和读取游戏 | 后端协议存在，前端未形成可用流程 | 还不是完整玩家功能 |
| 达到设定日期后结算 | 未接通 | 运行时长目前主要是清单元数据 |
| 胜利或失败 | 未定义 | 没有正式目标和终局 |

## 5. 当前不存在的典型游戏机制

以下内容不应被外部设计者误认为已经存在：

- 国家任务、竞选承诺或玩家 Mandate；
- 胜利、失败和正式结算；
- 任期、选举、支持率或政治合法性；
- 议会、利益集团、游说或社会反对；
- 可消耗的政治资本或行政能力；
- 已校准的政策调整成本；
- 普遍适用的政策实施滞后；
- 政策冷却、最小维持时间或调整上限；
- 内阁成员、顾问人格或部门冲突；
- 会主动响应玩家的外国政府；
- 外交谈判、条约、制裁博弈和联盟；
- 隐藏情报、预测误差、数据修订或顾问能力差异；
- 玩家可操作的家庭、企业或投资组合；
- 稳定的教程、任务链和难度曲线；
- 基于模拟状态动态生成的微观叙事；
- 正式的政策效果归因与反事实比较。

早期版本曾设计会议、席位、提案、投票、实施滞后、冷却和 Controller 等治理规则。
自由政策前端规格明确要求把这些规则从桌面沙盒移除。当前代码仍残留相关分支，但它们
不能被视为已经完成的玩法。

## 6. 当前玩法的优势

未来重构不应忽视已经建立的稀缺资产。

### 6.1 模拟不是静态数值面板

经济变量来自具有状态和行为的经济主体，而不是为了 UI 随机生成的数字。政策和冲击
会通过经济动力学产生跨期结果。

### 6.2 宏观与微观可以相互追溯

玩家既能看国家级指标，也能查看家庭、个人、企业和银行。这为“宏观政策如何改变普通
人和企业命运”的玩法提供了基础。

### 6.3 信息发布存在真实时间边界

指标具有发布时间和滞后，天然适合构建不完全信息、误判、修正和政策时机等玩法。

### 6.4 多经济体世界已经存在

贸易、资本、迁移、汇率和外生冲击已经给多国策略、传染、合作和竞争提供了底层条件。

### 6.5 政策 Registry 是统一真相

前端可以从引擎 Schema 自动生成政策控件，未来增加政策时不需要重新维护一套独立 UI
真相。

### 6.6 前后端可以支持多种游戏

同一经济引擎理论上可以承载：

- 完全自由的研究沙盒；
- 有任务和限制的政策经营游戏；
- 危机处置挑战；
- 多国策略游戏；
- RL 训练环境；
- 教学和实验产品。

这意味着未来不必把所有用户都塞进同一种玩法。

## 7. 当前玩法的核心问题

### 7.1 没有明确目标

玩家可以改变很多东西，但不知道自己为什么这样做。

当前没有：

- 本局使命；
- 优先级冲突；
- 阶段目标；
- 可接受失败；
- 最终评价；
- 结束条件。

一个国家不可能同时最大化增长、就业、价格稳定、财政安全、金融安全、平等和能源独立。
这本应是玩法的核心张力，但当前界面只是把这些维度同时展示出来。

### 7.2 决策几乎没有制度成本

自由政策规格取消了：

- 席位权限；
- 会议和投票；
- 行政容量；
- 调整成本；
- 冷却；
- 最小维持期；
- 最大单次调整幅度；
- 实施滞后。

这种模式适合实验室，但如果作为唯一游戏模式，玩家可能每天微调 102 个旋钮。策略会
退化为高频参数优化，而不是有承诺、有取舍的公共政策。

需要特别区分：

- **经济后果**：提高利率会影响需求、信贷和就业；
- **改变政策本身的成本**：信誉、行政资源、政治阻力、信息噪声和制度时滞。

当前主要存在前者，后者基本不存在。

### 7.3 没有稳定决策节奏

预算、利率、税制、最低工资、资本管制和汇率制度都呈现在同一个可随时编辑的工作台中。

现实中它们具有不同频率：

- 市场操作和紧急流动性可以日级响应；
- 利率通常在会议周期调整；
- 财政预算通常按季度或年度形成；
- 税制、福利和劳动法往往具有更长的立法和实施周期。

当前没有把这种频率差异转化为玩家能够理解的节奏，也没有建立“短期应急—中期稳定—
长期结构改革”的分层决策。

### 7.4 信息量远大于可行动信息

当前已经有大量专业图表，但玩家面对的问题是：

- 哪个异常最值得处理；
- 异常源头是什么；
- 哪些政策能够影响它；
- 多久以后才应观察效果；
- 哪些副作用正在积累；
- 是否需要继续等待而不是再次调整。

数据终端回答“发生了什么”，但还没有稳定回答“为什么发生”和“玩家现在有哪些有意义
的选择”。

### 7.5 因果反馈不足

玩家修改政策后，当前系统缺少：

- 图表上的政策生效标记；
- 预计传导路径；
- 政策前后对照；
- 对照基线或反事实；
- 变化来源分解；
- 决策复盘；
- 不确定性区间；
- 顾问对结果的解释。

因此玩家很难把数周或数月后的结果归因到某次决策，也难以从失败中学习。

### 7.6 开局存在数据空窗

为了保持真实发布日历，很多指标在 t=0 尚未发布。宏观判断通常需要至少两期公报。

这在模拟上合理，但在游戏上会造成：

- 玩家开局没有足够信息；
- 大量卡片显示“尚未发布”；
- 第一次有意义的决策来得太晚；
- 新玩家不知道该等待还是操作。

需要通过历史数据、任前简报、Nowcast、教程时间跳转或专门的开局阶段解决，而不是简单
泄露未来信息。

### 7.7 微观模块提供观察，但没有产生玩法

家庭、企业和员工页面包含丰富信息，但目前大多是被动浏览。

它们还没有稳定地承担：

- 政策受益者和受损者的叙事；
- 社会群体的诉求；
- 企业游说和投资反应；
- 典型家庭的生活变化；
- 危机传播的微观案例；
- 玩家决策的道德与分配后果。

因此这些页面很强大，却容易变成“数据博物馆”。

### 7.8 多国世界还没有形成战略互动

外国经济体会受到世界机制和冲击影响，但还没有成为清晰的策略主体。

当前缺少：

- 外国政府目标和政策行为；
- 对玩家政策的反应；
- 汇率、贸易、资本和移民政策博弈；
- 合作、报复、谈判与承诺；
- 跨国危机协调；
- 不同国家制度与目标之间的冲突。

所以当前是“多国模拟”，还不是“多国游戏”。

### 7.9 国家评分带有未经选择的价值判断

当前国家雷达图使用固定权重和阈值评价“均衡发展”。它会隐含地告诉玩家：

- 哪些结果是好结果；
- 不同目标应该占多少权重；
- 什么水平算成功。

这些规则没有经过任务、国家制度或玩家选择授权，也没有成为正式胜负条件。

更合理的未来方向可能是让评分来自：

- 场景使命；
- 国家 Profile；
- 玩家选择的执政纲领；
- 利益群体；
- 国际机构或债权人；
- 多套相互冲突的评价体系。

### 7.10 新建模拟过度面向研究用户

玩家还没学习系统，就需要理解：

- 跨境机制；
- 企业和银行结构；
- 人口参数；
- 生产函数；
- 国家能力；
- 102 个初始政策。

高级配置很有价值，但普通玩家需要预设、推荐值、渐进解锁和快速开局。否则游戏在开始
之前就要求玩家成为模型维护者。

### 7.11 模拟规模与界面表达矛盾

引擎目标是数百万 Agent，但当前前端仍允许逐个浏览家庭、成员、员工和企业。

需要明确三种对象：

1. **底层真实 Agent**：参与计算，但不要求玩家逐个管理；
2. **统计群体**：按收入、年龄、地区、行业等聚合，是主要决策对象；
3. **代表性主体**：从底层抽取、固定身份并持续追踪，用于叙事和解释。

如果不做这层区分：

- 小规模模拟缺乏宏观统计意义；
- 大规模模拟又会使逐户浏览失去可用性。

### 7.12 当前没有明确的玩家学习曲线

系统没有从简单问题逐步引入复杂系统。玩家一开始就能看到全部政策和全部指标。

缺少：

- 低风险教学任务；
- 单一目标场景；
- 逐步引入的新机制；
- 决策结果解释；
- 失败后的可操作建议；
- 从短期危机到长期治理的难度增长。

## 8. 当前必须先修复的产品断链

这些问题会干扰任何玩法测试，应与未来设计分开处理。

### P0：自由政策运行链路不一致

- 自由政策文档要求桌面默认使用 `free_policy`；
- Godot 原生适配器仍声明 `controller`；
- 开始菜单又把所有席位配置为 `null`；
- 实际结果可能是玩家能看到政策，却不能合法提交运行时调整。

应先选择并实现一个权威桌面合同。若桌面继续定位为自由沙盒，就应让原生协议、Schema、
快照、提交和端到端测试全部使用同一个自由政策流程。

### P0：有限运行时长没有形成终局

开始菜单允许配置结束日期或模拟天数，但当前运行时不会在该日期自动：

- 停止；
- 结算；
- 保存结果；
- 显示阶段评价。

这使“1 年、5 年、10 年”目前更接近元数据，而不是游戏规则。

### P0：返回主菜单与继续模拟冲突

当前返回主菜单会关闭会话并清除快照，但首页仍可能呈现“继续模拟”。继续按钮没有可靠
恢复同一世界。

### P1：保存读取没有完成玩家闭环

原生协议已经存在保存和读取能力，但 Godot 没有形成完整的存档列表、自动保存、版本
兼容提示和恢复流程。

### P1：部分设置只是界面状态

自动保存、保留数量、音频等设置尚未全部接入真实行为。界面不应承诺没有执行的功能。

### P1：场景文案与实际时长不一致

至少全球金融危机和自然灾害的 UI 文案与后端模板持续时间存在偏差。所有场景应从同一
Schema 读取说明和实际参数。

### P1：玩家国家选择已经从流程中消失

现行五步流程移除了政府页面，但没有在其他页面恢复玩家国家选择。因此玩家国实际固定
为第一国。

## 9. 未来设计应保留的原则

这些不是具体玩法方案，而是建议作为重构约束保留。

### 9.1 后端仍是通用经济模拟引擎

不要为了某一个前端玩法把胜负、剧情和 UI 状态硬编码进经济引擎。引擎应提供状态、
动作、事件、观测和存档；游戏层定义使命、评价、叙事和交互节奏。

### 9.2 自由沙盒继续存在

完全自由调整政策对研究、测试和高级玩家有真实价值。问题不在于它存在，而在于它目前
是唯一玩法。

可以考虑形成：

- 自由沙盒；
- 有约束的情景挑战；
- 长期国家经营或战役；
- 高级实验室。

### 9.3 不牺牲信息时间真实性

发布滞后、缺失和不完全信息是独特优势。未来可以增加 Nowcast、顾问预测和历史资料，
但不应让玩家默认全知。

### 9.4 政策结果必须来自引擎

任务、顾问和剧情可以解释或评价结果，但不应在前端伪造经济结果。家庭、企业、就业、
通胀、财政和金融后果应继续由模拟产生。

### 9.5 大规模 Agent 应转化为叙事和分配能力

数百万 Agent 不意味着玩家管理数百万人。它的价值在于：

- 更可信的分布；
- 群体差异；
- 尾部风险；
- 区域、年龄、行业和阶层异质性；
- 从真实底层状态抽取代表性故事。

### 9.6 政策自由度和游戏约束应分层

绝对范围与联动不变量属于引擎正确性；政治成本、会议周期、信誉和行政资源属于可选
玩法规则。两者不能混为一套难以关闭的限制。

## 10. 希望外部设计者重点回答的问题

以下问题可直接作为下一轮讨论提纲。

### 10.1 核心幻想

1. 玩家究竟扮演总统、政府、跨部门决策委员会、中央计划者，还是抽象的“国家意志”？
2. 玩家最希望感受到什么：救火、增长奇迹、制度建设、危机生存、国际竞争，还是政策
   实验？
3. 一局游戏结束时，玩家应该讲出怎样的故事？

### 10.2 核心循环

1. 一次有意义的决策循环应该覆盖几天、几周、一个季度还是一年？
2. 哪些政策允许紧急日级响应，哪些政策必须以更长周期处理？
3. 玩家每轮应处理多少个问题、比较多少个方案、调整多少个杠杆？
4. 如何让“不采取行动”和“等待更多数据”也成为有意义的策略？

### 10.3 目标与评价

1. 目标来自固定评分、场景任务、执政纲领、选民、国际约束还是玩家自选？
2. 如何表达增长、通胀、就业、分配、财政和金融稳定之间不可同时满足的冲突？
3. 游戏需要硬性的胜利失败，还是以任期报告和多维历史评价结束？
4. 如何避免存在一个永远正确的政策组合？

### 10.4 政策约束

1. 应不应该对改变政策本身收取成本？
2. 成本应是政治资本、行政容量、信誉、执行时滞、社会反弹，还是几者组合？
3. 如何避免玩家每天微调 102 个参数，同时不牺牲沙盒自由？
4. 是否应把单个旋钮组织成“政策包”“法案”“预算”“央行决定”和“紧急措施”？

### 10.5 反馈与可解释性

1. 如何把政策传导链呈现为玩家能学习的反馈，而不是直接泄露模型答案？
2. 如何区分政策效果、外生冲击、外国影响和自然经济波动？
3. 是否需要基线预测、多个顾问预测、政策情景对比和事后归因？
4. 家庭和企业如何成为宏观结果的可理解案例，而不是额外的信息负担？

### 10.6 多国玩法

1. 外国经济体由何种 AI 驱动？
2. 玩家与外国的主要互动是贸易谈判、汇率竞争、资本流动、移民、制裁还是危机协调？
3. 多国世界是合作型系统、竞争型策略游戏，还是玩家国家的外部环境？
4. 如何让不同国家 Profile 产生不同的可行战略，而不只是初始数值差异？

### 10.7 模拟规模

1. 5M Agent 应怎样改变玩法，而不仅是提高数值精度？
2. 前端应如何组合宏观统计、群体画像和代表性家庭/企业？
3. 哪些微观主体值得持续追踪并形成故事？
4. 是否需要地区、阶层、行业、代际和资产负债表等新的中间聚合层？

### 10.8 产品模式

是否应正式拆成三种入口：

| 模式 | 目标用户 | 约束 | 评价 |
|---|---|---|---|
| 自由沙盒 | 研究与高级玩家 | 只保留引擎不变量 | 无强制胜负 |
| 情景挑战 | 普通玩家与教学 | 有限目标、时间和政策条件 | 明确阶段评价 |
| 国家经营 / 战役 | 核心玩家 | 长期制度、国内与国际约束 | 任期、国家轨迹或历史评价 |

这只是待讨论的候选结构，不是已经确定的产品决定。

## 11. 建议外部 AI 输出的内容

基于本文，请外部设计者不要只提出更多页面、指标或抽象概念，而是至少交付：

1. 一句话玩家幻想；
2. 30 秒、5 分钟、1 小时三个尺度的玩家循环；
3. 一局游戏的开始、中段、危机、恢复和结束；
4. 玩家资源、约束和失败来源；
5. 政策操作的组织方式与决策频率；
6. 数据、顾问、预测和事后复盘的交互；
7. 微观家庭与企业如何服务宏观玩法；
8. 外国政府和国际关系如何行动；
9. 自由沙盒与正式游戏模式如何共存；
10. 一个可以用当前引擎能力先做出来的最小可玩版本；
11. 哪些设想需要新增引擎能力，哪些只需要游戏层开发；
12. 可用于验证“真的好玩”的试玩指标和失败标准。

建议同时明确：

- 哪些现有功能应保留；
- 哪些应隐藏到高级模式；
- 哪些应重构；
- 哪些应删除；
- 哪些只是长期愿景，不进入首个可玩版本。

## 13. 可直接复制给外部 AI 的任务说明

> 我们正在开发一个前后端分离的多经济体 Agent-based 经济模拟产品。后端是通用 C++
> 模拟引擎，未来目标规模约 5M Agent；Godot 只是当前前端。现有产品已经有完整的世界
> 创世、国家结构、约 102 个政策、自然日推进、延迟发布的宏观数据、家庭、个人、企业、
> 股市、银行、多国贸易/资本/迁移和外生冲击可视化。
>
> 当前产品仍像一个经济实验室，不是完成的游戏：缺少玩家身份、目标、决策成本、稳定
> 节奏、政策归因、外国策略主体、阶段评价和终局。自由政策沙盒必须保留，但不必继续
> 作为唯一模式。现有前端布局可以推翻，经济结果必须继续来自模拟引擎。
>
> 请基于本文完整现状，为它设计一个真正可玩的经济经营/策略游戏。先定义玩家幻想和
> 核心循环，再设计目标、约束、反馈、微观叙事、多国互动与一局游戏的结构。请明确区分：
> 当前引擎已支持的能力、只需游戏层实现的能力、必须新增的引擎能力。最后给出一个能够
> 快速验证乐趣的最小可玩版本，而不是直接提出完整的大型愿景。
