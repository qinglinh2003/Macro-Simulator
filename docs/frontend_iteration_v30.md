# 前端审阅与迭代计划 v30

**审阅基线**：`feat/frontend-design-v29` @ `24d5fa2`
**产品目标**：保留 v29.1 已确定的浅色政策终端风格，把界面从“功能完整的宏观仪表盘”推进为“信息有主次、节奏顺畅、决策有反馈的金融模拟经营游戏”。

## 3. 本轮边界

本轮不改变既有浅色设计系统，不引入图片素材，不在前端添加经济推断，也不伪造目标或政策效果。所有新交互继续遵守：Python worker 单写者、会议边界冻结、Policy/Controller/Shock 为唯一权威。

## 4. P0.6 政策工作台交互裁决

### 4.1 信息层级

- 左栏默认展示当前席位的“本会议题”，只保留当前决策窗口实际授权的主题与政策；需要学习制度时可切换到“全部政策”。
- 搜索始终跨越五个席位，结果同时显示归属席位；从提案篮点“编辑”会返回权威归属席位与主题页。
- 收起行固定展示中文名称、canonical 字段、`当前值 → 草稿/待生效值` 和状态。状态明确区分：本会可调整、未入篮草稿、已加入提案篮、提案篮待更新、待生效与仅查看制度。
- 每个主题签显示政策数和草稿/提案数；有当前会议授权的主题使用实心标记，避免玩家逐页试错。

### 4.2 调整方式

- 数值政策提供两条等价路径：加减按钮用于探索，精确输入用于有目标的操作；输入框支持点击“应用数值”和回车提交。
- 人类可读值使用百分比、倍数、天数或套/年等单位；精确输入始终保留 Registry 的 canonical 模型值，避免显示换算污染协议。
- 编辑器同时显示单档步长、本次会议允许范围、制度全域和原始模型值。超出本次范围的精确输入夹到最近合法边界。
- 枚举和布尔制度迁移统一触发二次确认；货币手动模式、手动利率、联系汇率和锚国给出同批动作提示，但不在前端伪造联合校验。

### 4.3 草稿与提案篮

- 调整值先形成“未入篮草稿”；只有点击“加入提案”后才进入跨席位原子批。
- 已入篮政策再次编辑时，旧提案继续保留并标记“有新草稿 / 待更新”；玩家必须明确点击“更新提案篮”，因此提交目标不会在后台静默变化。
- “恢复当前值”清除草稿；“移出并撤销”同时移除提案项和草稿。与当前值相同的草稿不会生成空动作。
- 提案篮显示各动作的起点、目标、草稿同步状态和行政容量合计，并支持一键返回对应政策编辑器。

### 4.4 验收口径

- 1440×900 默认窗口和 1280×800 紧凑窗口均无横向滚动、栏位溢出或核心操作裁切。
- 会议首屏在不展开旋钮时，一个主题页可完整浏览；展开后允许左栏纵向滚动，并保留滚动位置。
- 本轮只消费既有 Registry、DecisionContext、Pending 和 world schema，不改变经济数值、政策校验、裁决或生效时序。
