# V23 Plan Review — 修订要求与补丁设计

> **状态：REVIEWED DRAFT（2026-07-14）**
>
> **评审基线：** [`PLAN_v23.md`](./PLAN_v23.md)，包含七个 Tier-1 问题。
>
> **用途：** 本文是 `PLAN_v23` 的修订伴随文档，不直接替代原计划。实现前应先把本文的
> 事实纠正、设计边界、依赖顺序和验收标准回填到主计划。

## 1. 总结

七个 Tier-1 条目都抓到了真实问题，但原计划把若干“代码事实”“因果假设”和“候选修复”
混在了一起。需要统一修正的地方有四类：

1. 把条件性因果写成已证实结论。例如，资本成本缺失会造成额外的成本侧通缩压力，但仅凭
   代码不能证明它解释了历史运行中的全部通缩，也不能证明央行是或不是最终根因。
2. 把“主要直接渠道缺失”写成“完全没有渠道”。模型仍有债务现金流、资产估值、住房套利、
   债券估值和企业进入等利率渠道，只是它们间接、不完整，部分还耦合错误。
3. 候选补丁缺少量纲、会计和市场定义。直接把资本实物单位加到名义净值，或把原始政策利率
   塞进投资/消费公式，会制造新的错误。
4. 计划内部的实施顺序冲突。价格指数是独立存在的测量缺陷，不应等成本侧修复后再决定“是否
   需要”；但把新 CPI 接入央行、把新 GDP 接入财政，以及修改名义锚规则，应放在基础机制修好
   并完成重审之后。

### 1.1 逐项结论

| Tier-1 | 结论 | 主计划必须修改的核心内容 |
|---|---|---|
| #1 价格指数 / 名义锚 | 指数缺陷确认；名义锚根因未证实 | CPI 修复不是纯观察；CPI 与 GDP deflator 分离；Patch #2 保持条件性 |
| #2 GDP | 核心问题确认；原聚合表述不准确 | 当前是 C 部门产出估值，不是支出法的 C；不能直接相加 E 部门总产出；现有 `va` 不能直接升格为 GDP |
| #3 C 部门未满足需求 | 缺陷确认；“现成数据已足够”不成立 | 匹配器只保留成交，不保留可归因的未成交 footfall；必须先定义归因规则 |
| #4 企业/银行 P&L | 企业侧确认；银行侧需要收窄 | 核销已经直接打击银行资本，只是没有进入银行利润流量；必须拆分 EBITDA/EBIT/税前利润/净利润 |
| #5 资本成本与定价 | 缺陷确认；因果措辞过强 | 资本并非“任何地方都免费”；它有现金购置和实物折旧，只是在定价、损益和部分决策中未计价 |
| #6 抵押品 | 缺陷确认；现有替代量不可直接复用 | `cash + capital - debt` 混加名义金额和资本实物单位；抵押借款基础必须使用价格、折扣和受偿规则 |
| #7 货币政策传导 | 主要诊断确认；标题和补丁不准确 | 改成“缺少主要直接总需求渠道”；先建利率传导和合约层，再接投资、消费、信贷与按揭 |

## 2. Tier-1 #1：价格指数与名义锚

### 2.1 保留的判断

当前 `price_index = total_revenue / total_sales_u` 是当期成交的 unit-value index
（[`metrics.py:218`](../../macro_sim/reporting/metrics.py)）。它会同时随价格和销售构成变化，
因此不能把全部变动解释为同一篮子商品的通胀。央行又通过 `_prev_inflation` / `_infl_ema` 消费
这一信号（[`central_bank.py:20`](../../macro_sim/systems/central_bank.py)），测量误差会进入行为。

### 2.2 主计划需要纠正

- “pure observation change”是错误表述。只要新指数接入央行，它就是行为变更；如果继续用于实际
  产出、财政分母或其他指数化规则，也会继续改变模型路径。
- “Laspeyres/Paasche fixed-basket”需要拆开。Laspeyres/Lowe 使用基期或预定权重；Paasche 使用
  当期数量权重，不是严格意义上的固定篮子。
- CPI、部门生产者价格和 GDP deflator 不是一个对象。不能再让 C 部门成交均价同时承担居民
  生活成本、央行通胀目标和全经济产出缩减指数三个职责。
- 固定篮子也必须定义企业进入、退出、零成交、缺货、必要品/奢侈品分层和定期换基规则；否则
  指数会因缺失价格或幸存者选择产生新偏差。

### 2.3 修订后的补丁

1. 新增居民消费价格指数 `cpi`：优先使用预定类别权重和同类价格相对数；类别内明确匹配样本、
   缺失价格和换基规则。
2. 保留 `consumption_unit_value` 作为市场构成/成交均价诊断，不再命名为通用 `price_index`。
3. GDP 使用单独的名义/实际核算和隐含 deflator，见 Tier-1 #2。
4. 分离两个开关：
   - `v23_price_indices`：只生产新指标；
   - `v23_policy_uses_cpi`：央行开始消费新 CPI。
5. 旧字段在迁移期保留兼容别名，并在输出元数据中写明定义，避免历史实验静默换义。

### 2.4 验收

- 所有个体价格固定、销售构成变化时，CPI 通胀应为零或仅有定义明确的换基误差。
- 篮子和销量不变、所有价格统一上涨 `x%` 时，CPI 应上涨 `x%`。
- 企业进入/退出、某类别零成交和全面缺货均不得产生 NaN、跳到零或使用未来信息。
- 仅开指标开关时，除新增观测字段外，代理行为和账本路径不变；政策开关关闭时央行路径不变。

### 2.5 名义锚 Patch #2 的地位

v19 的冻结央行对照说明不同利率规则与通缩路径相关，但不能单独证明“Taylor rule 把生产率
冲击误判为需求不足”是根因。价格信号污染、日频/年频量纲、资本成本缺失、银行收入再分配、
传导渠道缺失和规则本身都可能贡献结果。

因此 Patch #2 必须继续是**重审后的条件补丁**。在 CPI、GDP、成本、P&L 和利率传导修好以前，
不预先选定 NGDP level target 或生产率调整通胀目标。重审应比较目标偏差、产出/就业代价、利率
边界停留时间和冲击响应，而不是只看最终平均通胀。

## 3. Tier-1 #2：GDP 聚合

### 3.1 保留的判断

当前 `nominal_output = total_produced * price_index`
（[`metrics.py:1018`](../../macro_sim/reporting/metrics.py)），其中 `total_produced` 只汇总 C 部门。
这个分母还被财政预算和大量 `*_to_gdp` 比率消费，所以不仅是展示错误。

### 3.2 主计划需要纠正

- 当前量不是支出法中的“消费 C”，而是 C 部门当期**生产量**乘以 C 部门 unit value；其中包含
  未售库存，也未按实际最终支出计价。
- 不能把 C、K、E 的部门总产出直接相加。企业使用的能源属于中间投入，直接加入会重复计算；
  只有最终能源消费或能源部门增加值进入 GDP。
- K 部门只有被购买并形成固定资本或库存变化的部分进入支出法投资，不能把全部 K 产量自动
  当作 `I`。
- 现有 `va = wagebill + max(0, profit)` 也不能直接升格：它截断负利润，`profit` 当前是 EBITDA，
  且产品税、补贴、中间投入和折旧口径尚未完成对账。
- 日流量与年化存量比率必须统一。目前不同 `*_to_gdp` 指标并未全部采用同一时间基准。

### 3.3 修订后的补丁

建立一个小型 national-accounts 层，同时计算并对账：

- **支出法名义 GDP**：家庭最终消费 + 政府最终消费 + 私人/公共固定资本形成 + 各部门库存变化；
  企业能源中间消费不重复计入。
- **生产法名义 GDP**：各部门总产出减中间消费，加产品税减补贴。
- **收入法交叉检查**：劳动报酬 + 毛营业盈余 + 生产和进口税减补贴；若展示净口径，再单列资本
  消耗，不能在 gross GDP 中重复扣除折旧。
- **实际 GDP**：按部门固定价格或链式数量指标计算，并派生 GDP deflator；不得用 CPI 直接缩减
  全经济 GDP。

财政规则和 `*_to_gdp` 比率使用同一个滞后名义 GDP 字段，但通过独立的
`v23_fiscal_uses_gdp` 开关接入，避免“新增正确指标”和“改变财政反馈”被绑在一次实验中。

### 3.4 验收

- 三种核算口径在模型定义允许的误差内对账，并报告 reconciliation residual。
- 企业能源采购只能作为买方中间投入扣除、卖方产出计入一次。
- 库存增加计入投资，库存出售相应减少库存投资；不得把生产和销售同时计入最终需求。
- 政府消费与政府投资分开，财政转移支付不计入 GDP。
- GDP 分母切换后重新校准并审计财政赤字、债务、信用、偿债和货币流通速度比率。

## 4. Tier-1 #3：C 部门未满足需求信号

### 4.1 保留的判断

C 企业的预期更新读取 `sales_prev + rationed_prev`
（[`planning.py:50`](../../macro_sim/behavior/planning.py)），但 C 市场只生成聚合 `_unsat_ratio`
（[`goods.py:205`](../../macro_sim/systems/goods.py)）。因此缺货时，企业无法观察未成交需求，预期
存在向下偏差。

### 4.2 主计划需要纠正

“order book already exists, so the data is there”并不准确。通用匹配器只返回成交 `Trade`，不返回
每个买家的剩余预算/数量、尝试过的卖家或缺货时本来会选择的卖家
（[`matching.py:63`](../../macro_sim/markets/matching.py)）。当前只能知道总未花预算，不能唯一、
无偏地把它分给企业。

K 部门把未满足订单平均分给全部 K 企业是一种简化，不应不加审查地复制到 C 部门；在随机、
价格比较和 preferential matching 下，它可能把需求分给买家从未看到的高价或低吸引力企业。

### 4.3 修订后的补丁

1. 扩展市场执行结果，返回每个订单的剩余需求/预算以及协议定义的 choice set / exhausted sellers。
2. 明确 footfall 定义：它是买家在卖家有货时本会购买的反事实数量，不是未花的名义预算本身。
3. 按匹配协议归因：随机协议按被访问/抽样概率，价格比较按样本内合格卖家，preferential 协议按
   当期权重。无法识别时保留聚合信号，不伪造精确的企业级观测。
4. 必要品和奢侈品两个 session 分开计算，避免把必要品缺货错误分给奢侈品企业。
5. 信号只进入下一期预期，不产生收入、库存、税或账本流量；开关关闭时保持旧随机数调用和路径。

### 4.4 验收

- 充足库存时企业 footfall 总和为零；全面缺货时其总和与协议定义的未满足实物需求一致。
- `sales + rationed_demand` 不得超过已定义的总意向需求。
- 启用信号不能当期增加销售、收入或货币，只能影响后续计划。
- 单卖家、多个价格、分层市场、政府采购和 preferential matching 均有确定性测试。

## 5. Tier-1 #4：企业与银行 P&L

### 5.1 保留的判断

企业 `profit = revenue - wagebill - energy_cost_used`
（[`settlement.py:40`](../../macro_sim/systems/settlement.py)）是 EBITDA 式流量。利息和会计折旧没有
进入税基、可分配利润和估值所使用的利润字段。银行 `profit = interest_income`
（[`credit.py:122`](../../macro_sim/systems/credit.py)）没有合同存款利息、其他资金成本和信用损失
流量。

### 5.2 主计划需要纠正

- 贷款核销并非“没有打击银行”。`Ledger.write_off` 已同步减少贷款资产和银行资本
  （[`ledger.py:352`](../../macro_sim/core/ledger.py)）。缺失的是逐银行损失流、利润表确认和一致的
  分红约束，而不是资产负债表损失本身。
- 在目标资本率开启时，分红按“资本超过目标”的空间计算；核销可能已经令分红归零。因此“银行
  在信用崩溃中始终照常分红”过强。准确说法是：非目标资本路径仍可按未扣损失的毛利分红，且
  两条路径都没有一张可解释的损益表。
- 现有按存款比例向家庭分配银行收入是利润分配/闭环机制，不是合同存款利息，不能直接当作资金
  成本。
- 债务税盾取决于税制设计。利息可扣除可以作为默认候选，但应显式配置扣除范围和上限，不能写成
  无条件会计真理。
- 毛 GDP 中资本消耗属于毛营业盈余的一部分；企业净利润扣折旧后，收入法 GDP 必须把资本消耗
  加回，避免 GDP 被重复扣减。

### 5.3 修订后的补丁

企业逐期记录：

```text
revenue
- intermediate inputs
- compensation
= EBITDA
- depreciation
= EBIT
- accrued interest expense
= pre-tax income
- profit tax
= net income
- dividends
= retained earnings
```

银行逐期记录：利息收入、存款/批发/同业资金成本、手续费（若存在）、信用损失/拨备、税前利润、
净利润和分红。至少把实际核销按银行归属记录；若引入预期信用损失拨备，必须与随后核销对账，
不能重复确认。

同时需要：

- 给利息选择明确的现金制或权责发生制。若采用权责发生制，未支付利息进入应付/逾期或资本化，
  不能像当前现金上限那样静默消失。
- 企业和家庭贷款服务都记录 borrower-level、bank-level 的利息流，供 P&L 和冲击分解使用。
- 分红同时受 `max(0, distributable net income)`、现金和监管资本约束；资本目标不能凭空创造可分配
  利润。
- 保留旧 `profit` 字段的迁移定义或明确改名，逐个审计税收、进入退出、权益估值、劳动份额和指标
  消费者。

### 5.4 验收

- 每笔利息在借款人费用、银行收入和账本转移上金额一致；存款利息同理。
- 每笔核销只打击一次资本，并在逐银行损益与贷款账面减少中可对账。
- 高杠杆企业在其他条件相同时税前利润更低；零债务企业不产生利息费用。
- 折旧费用与资本账面价值/实物折旧桥接，且不会把资本购买直接当期全额费用化。
- 无可分配净利润或资本不足时不得分红。

## 6. Tier-1 #5：资本成本、定价与通缩假设

### 6.1 保留的判断

当前 `unit_cost` 只有劳动、能源和规模项
（[`planning.py:101`](../../macro_sim/behavior/planning.py)），资本服务没有进入成本加成定价；企业
利润也未扣折旧和利息。因此资本深化会在其他条件不变时降低单位劳动成本，而定价器看不到替代
劳动的资本服务成本。

### 6.2 主计划需要纠正

- “capital is a free input everywhere”不准确。企业购买 K goods 会付现金，资本会实物折旧，资本也
  被权益账面值使用。准确范围是：**资本服务未进入全成本定价和 P&L，资本使用成本未进入主要
  投资决策**。
- “定价规则制造了我们追踪的全部通缩”目前是待检验假设。代码能证明存在向下偏差的方向，不能
  单凭静态路径给历史通缩方差分解或排除需求、货币、市场构成等原因。
- 只把 `delta_K * K` 的实物单位除以产量并加到名义单位成本仍有量纲错误；必须使用 K goods 的
  价格/重置成本。
- P&L 的实际债务利息、投资决策的机会成本和定价中的长期资本服务成本是相关但不同的概念，不能
  共用一个含糊的 `capital_cost` 后重复计算。

### 6.3 修订后的补丁

定义名义资本服务成本，例如：

```text
capital_service_cost
    = replacement_price_of_capital
    * capital_employed
    * real_user_cost_per_tick
unit_capital_cost
    = capital_service_cost / planned_output
```

`real_user_cost` 至少明确折旧、有效融资/机会成本、预期通胀或资本价格变化；具体形式与 Tier-1 #7
共享，但参数必须统一到 tick 量纲。定价器使用劳动 + 中间投入 + 资本服务的长期单位成本；P&L 则
分别确认会计折旧和实际融资费用。

### 6.4 验收

- 在工资、能源价格、markup、产量和资本品价格受控的单元实验中，提高资本不再因遗漏资本服务
  而机械性压低全单位成本。
- `delta_K=0`、资本机会成本为零时，新增资本成本项按定义归零。
- 资本品价格翻倍时，资本服务成本按设计变化，不能仍按“一单位资本 = 一单位货币”计价。
- 用配对运行量化该补丁对通胀的贡献；“消除历史通缩”是需要检验的宏观假设，不是硬编码验收。

## 7. Tier-1 #6：资本与库存作为抵押品

### 7.1 保留的判断

企业授信使用 `NW = deposits - debt`
（[`planning.py:240`](../../macro_sim/behavior/planning.py)），生产资产不影响借款能力，因此缺少
资产价格—抵押价值—信用—投资这一金融加速器渠道。

### 7.2 主计划需要纠正

- 权益模块现有 `cash + capital - debt` 把名义现金/债务与资本实物单位直接相加
  （[`equity.py:20`](../../macro_sim/systems/equity.py)）。它不是可以直接复用的“正确净值”，而是
  另一个需要一并修正的量纲问题。
- 库存也不能按实物数量直接进入名义抵押基础，应按成本与可变现价值孰低或其他明确估值，并应用
  流动性折扣。
- 会计净值、抵押借款基础和偿债能力是三个对象。把资产加入 `NW` 后继续沿用
  `room = kappa * NW - debt` 可能重复计入债务或产生过强的顺周期杠杆。
- 如果违约时银行不能取得、处置抵押物并降低损失，机制严格来说只是“资产相关授信上限”，不是
  完整抵押贷款。名称和实现必须一致。

### 7.3 修订后的补丁

1. 建立统一的企业资产估值层：现金、资本重置/可变现价值、库存价值、债务和所有者权益分别记录。
2. 定义 eligible collateral 和 haircut，例如 `h_K * P_K * K + h_I * inventory_value`。
3. 授信同时考虑抵押 LTV、现有优先债权、银行供给约束，以及基于 EBITDA/现金流和利率的偿债
   能力；不要只用一个杠杆倍数承担全部风险判断。
4. 明确抵押权和违约回收。若 v23 暂不实现资产处置，字段和文档应称为 borrowing-base proxy，
   并把完整回收列为同一补丁的未完成条件。
5. 权益估值、抵押估值和 national accounts 共享价格来源，但可使用不同的估值口径和 haircut。

### 7.4 验收

- 相同现金流和债务下，提高有价格的合格资产价值应弱增加授信空间；提高 haircut 应弱减少空间。
- 资本价格为零或资产不合格时不得产生抵押额度。
- 现有债务不能在净值和额度公式中被错误地重复扣除或遗漏。
- 资产价格冲击的 q、抵押和投资响应可分别观测；账本中不因“重估”凭空创造现金。
- 若实现抵押处置，银行回收、借款人资产减少和剩余核销三者必须对账。

## 8. Tier-1 #7：货币政策对总需求的传导

### 8.1 修订后的标题

> **货币政策缺少对总需求的主要直接传导渠道；现有间接渠道不完整且存在错误耦合。**

### 8.2 保留的判断

以下决策目前不直接读取利率：

- 目标资本 `K* = v * demand_expected`（[`planning.py:206`](../../macro_sim/behavior/planning.py)）；
- 家庭消费预算（[`planning.py:265`](../../macro_sim/behavior/planning.py)）；
- 企业和家庭信贷申请量（[`planning.py:231`](../../macro_sim/behavior/planning.py)）；
- 按揭资格与金额只看现金和 LTV，不看利率、月供或 DSTI
  （[`housing/market.py:123`](../../macro_sim/housing/market.py)）。

因此模型确实缺少投资使用成本、储蓄/跨期替代、利率敏感的信用需求和按揭负担渠道。

### 8.3 主计划需要纠正

“NO transmission”“only debt service and weak q”“央行不能刺激”都应删除。现有渠道包括：

- 全部存量企业/家庭债务按当前贷款率支付利息，产生借款人—银行—家庭的现金流再分配
  （[`credit.py:71`](../../macro_sim/systems/credit.py)）；
- 政策利率进入 residual-income 估值和 Tobin's q，再影响投资
  （[`equity.py:124`](../../macro_sim/systems/equity.py)）；
- 投资性住房把租金收益率与一个年化“存款率”比较
  （[`housing/market.py:109`](../../macro_sim/housing/market.py)）；
- 利率影响债券市值、银行经济资本、企业/银行进入和贷款银行选择。

这些渠道不能简单称为“弱”：例如 q premium 中存在除以很小日利率的非线性，实际强度必须用冲击
实验测量。它们还包含三项明显耦合问题：

1. 存量贷款没有 vintage/固定浮动属性，全部立即按当前政策利率重定价。
2. 住房模块比较“存款收益”，但银行没有真正支付合同存款利息。
3. 银行估值使用 `max(policy_rate, 0.01)` 的折现率下限，日频低利率区间会与政策率脱钩
   （[`banking.py:221`](../../macro_sim/systems/banking.py)）。

所以当前宽松政策可能通过债务减负、q 或住房需求刺激，也可能因银行收入/分红下降等再分配效应
被抵消。净方向是待测结果，不能预注册成无条件恒正。

### 8.4 修订后的补丁

#### A. 利率与合约基础层

- 明确 `policy_rate`、无风险/国债利率、存款率、企业贷款率、消费贷款率和按揭率。
- 所有利率提供唯一的年化—每 tick 转换函数；禁止在业务模块中散落 `* 365` 或未经转换的相加。
- 建立政策率到各零售利率的 pass-through、spread、调整速度和下限。
- 贷款记录 origination rate、固定/浮动类型、repricing interval、期限和剩余本金；存量贷款不再全部
  瞬时重定价。
- 真正支付存款利息并进入家庭收入与银行资金成本后，住房和消费模块才可引用存款回报。

#### B. 投资渠道

- 使用企业实际面对的**预期实际 user cost**，而不是原始政策率 `r`：贷款/机会成本 + 折旧 - 预期
  资本价格变化，并考虑资本品价格相对产出价格。
- 对 Cobb-Douglas 企业，可从边际资本产出等于 user cost 推导 `K*` 或 `K*/Y`，再保留 partial
  adjustment；不能只把固定 `v` 随意除以 `(r + delta)`。
- 零利率附近需要平滑、上下界和预期处理，防止 `K*` 发散。

#### C. 家庭需求与信贷渠道

- 在实际存款收益存在后，引入可解释的目标财富/储蓄规则，或简单且有界的 Euler/CRRA 近似；区分
  净储户和浮息借款人，避免一个统一 `r` 系数掩盖再分配。
- 消费信用申请和授信加入利率、预期偿债额、收入和现有债务。
- 按揭加入按揭率、期限、月供/每 tick 付款、DSTI 和压力测试；LTV 仍保留为抵押约束。
- 汇率渠道在封闭经济版本中可明确列为 out of scope，而不是误报为 bug。

### 8.5 验收

使用相同初始状态、相同随机数和相同非货币政策，执行临时加息/降息冲击，逐层输出：

- 各零售利率及 pass-through lag；
- 存量贷款重定价比例、利息支付与存款收入；
- 目标资本、投资订单、企业信贷申请/批准；
- 消费预算、家庭信贷、按揭资格/发放和投资性住房需求；
- q、债券市值、银行利润/资本/分红；
- GDP、就业和通胀。

组件级方向可以硬验收：降息在其他条件固定时降低浮息债务服务和预期实际 user cost，并弱增加
利率敏感的目标投资/可负担信贷。总 GDP 和通胀的符号、幅度和滞后应作为模型结果及校准目标，
不作为所有状态下必须满足的程序不变量。

## 9. 跨补丁的共同数据模型

为避免八个 patch 各自引入一套互不兼容的“价格/成本/净值”，v23 应先定义以下共享对象：

| 共享对象 | 最小字段 | 主要消费者 |
|---|---|---|
| Price indices | CPI、部门价格、GDP deflator、base period/weights | 央行、实际量、福利指标 |
| National accounts | C、G、固定资本形成、库存变化、中间投入、三法 GDP、residual | 财政规则、所有 GDP 比率 |
| Rate curve / pass-through | 年化率、tick 率、spread、调整速度、下限 | 贷款、存款、债券、住房、投资 |
| Loan contract | 本金、origination rate、rate type、repricing、maturity、arrears、bank | 债务服务、P&L、DSTI、冲击实验 |
| Firm asset valuation | `P_K*K`、库存价值、haircut、债务、equity | q、抵押、进入退出、P&L |
| Firm P&L | EBITDA、折旧、EBIT、利息、税、净利润、分红 | 税收、估值、进入、收入法 GDP |
| Bank P&L | 利息收入、资金成本、信用损失、净利润、分红 | 银行资本、估值、进入退出 |

共享对象不意味着所有模块使用完全相同的估值口径。例如 national accounts 可使用当期生产价格，
抵押使用可变现价值和 haircut，权益估值使用持续经营口径；但每个口径都必须有名称和单位，不能
继续把实物单位和名义货币无标签地相加。

## 10. 修订后的实施顺序

原计划一处写价格指数“do first”，另一处又要求先修成本并在之后才决定价格指数是否需要，二者
冲突。建议改为以下依赖顺序：

### Phase 0 — 基线与定义冻结

- 固定同种子 baseline digest、关键历史场景和冲击 harness。
- 写明所有存量/流量、实物/名义、每 tick/年化单位。
- 给旧 `profit`、`price_index`、`nominal_output` 字段建立消费者清单。

### Phase 1 — 测量层，暂不接入行为

- 实现 CPI / unit value 分离和 GDP 三法核算。
- 修复就业人数与效率单位混用，保留两个独立指标。
- 只输出并对账新字段，不立即切换央行和财政规则。

### Phase 2 — 会计、资产和利率基础层

- 实现企业/银行 P&L、逐借款人/逐银行利息和核销流。
- 实现资本/库存名义估值以及贷款合约/vintage/pass-through。
- 实现真实存款利息和银行资金成本。

### Phase 3 — 成本、抵押与总需求决策

- 资本服务进入全成本定价；会计折旧进入 P&L。
- 有价格和 haircut 的抵押基础进入企业授信，并补违约回收语义。
- user cost 进入投资，利率/偿债进入消费信贷和按揭，家庭储蓄规则读取真实回报。
- C 部门 footfall 作为独立补丁接入预期。

### Phase 4 — 行为消费者切换与综合审计

- 分别开启 `policy uses CPI`、`fiscal uses GDP`，不要用一个总开关掩盖归因。
- 运行 P&L/金融加速器、价格侧、货币传导和名义锚的配对实验。
- 只有 clean CPI + correct GDP + full cost/P&L + live transmission 下仍不能稳定名义锚时，才进入
  Patch #2 的规则选择。

## 11. 统一验收门槛

每个补丁除自己的机制测试外，还必须通过：

1. **Flag-off 回归：** 默认关闭时保持预注册的同种子状态/账本 digest；若新增观测字段导致输出
   schema 改变，行为状态 digest 必须单独保持一致。
2. **会计守恒：** A5、证券、人口 claims、利息双边流、资产处置和三法 GDP reconciliation 均有
   明确 residual 与容差。
3. **量纲检查：** 禁止名义金额与实物单位直接相加；禁止年率与 tick 率直接相加或比较。
4. **组件测试优先：** 先验证局部偏导和会计恒等式，再解释宏观 IRF。
5. **配对冲击：** 同初始快照、同随机流、一次只改变一个机制或政策路径，并输出渠道分解。
6. **不预注册过强结论：** “金融加速器一定增强”“央行一定刺激”“通缩一定消失”属于经验结果；
   硬验收应限定在可由设计保证的局部方向、守恒、边界和时序。

## 13. Minor notes 的处理

- **失业率单位：** 不只修一个公式；新增就业人数（heads）和有效劳动投入（efficiency units）两个
  指标，央行与 Phillips 检验明确选择前者。
- **重复人均产出键：** 选一个 canonical 名称，另一个保留一段迁移期并标成 alias，避免历史分析
  脚本静默断裂。
- **两种企业净值：** 不应简单“统一到资本 inclusive”；先完成名义资产估值，再分别命名 accounting
  equity、equity-market book value 和 lending collateral base。
- **库存不是资产：** 与 Tier-1 #2/#6 共用库存估值；同时进入库存投资、企业资产和抵押 haircut，
  但不能重复计入 GDP 或净值。

完成以上修订后，v23 才是一批可归因、可验证的 release-blocker patches，而不是一次把测量、会计、
行为和政策规则同时切换的单体改造。
